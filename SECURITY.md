# Security Policy

## Supported versions

This repository is documentation-only. Security fixes are applied to the latest version on the default branch; older snapshots are not maintained separately.

## Reporting a vulnerability

Please do not disclose a suspected vulnerability, exposed access value, personal information, or another sensitive finding in a public issue, discussion, or pull request.

Use the repository's **Security** tab to submit a private vulnerability report when GitHub private vulnerability reporting is enabled. If that option is unavailable, contact the repository owner privately through a non-public channel listed on the owner's GitHub profile. Share only the minimum information needed to reproduce and assess the issue.

A useful report includes:

- the affected file or workflow step;
- the impact and realistic attack scenario;
- reproducible steps or a minimal proof of concept;
- suggested remediation, if known; and
- whether any sensitive material may already have been exposed.

Please allow a reasonable period for acknowledgement, investigation, and remediation before any coordinated public disclosure. This policy does not authorize accessing other people's systems or data, disrupting services, or violating applicable law.

## Scope note

The repository provides documentation, prompts, templates, and local audit utilities. Services, models, datasets, notebooks, and third-party tools that users choose to connect remain subject to their own security policies.
